# 网络与代理（重要）

## 一句话结论

本项目**依赖代理 / VPN** 才能搜索和下载。目标站点在多数网络环境下无法直连，
不挂代理时「搜索 / 下载 / 检查更新」会一直卡住或超时；**已下载的内容可以完全离线阅读**。

## 功能对网络的依赖

| 功能 | 需要代理？ |
|---|---|
| 浏览已下载库、阅读器、换主题、续读 | ❌ 不需要（纯本地） |
| 导出 PDF / ZIP、删除（回收站）、历史 | ❌ 不需要 |
| **搜索、查询详情** | ✅ 需要 |
| **下载 / 追更检查更新** | ✅ 需要 |

## 两种可用方式

### 方式一：TUN / 系统级代理（推荐，程序无需改配置）

以 Clash 系工具（Clash Verge / FlClash / Mihomo）为例：

1. 打开「TUN 模式」（有的叫「虚拟网卡」「Tun Mode」）
2. 开启后，系统 DNS 会解析到 `198.18.x.x` 这类 fake-IP，说明流量已被接管
3. 直接启动本程序即可

> 判断是否生效：`18comic.vip` 的 DNS 解析结果落在 `198.18.0.0/15` 网段 = TUN 已接管。

### 方式二：在 `option.yml` 里指定 HTTP 代理（不开 TUN 时）

```yaml
client:
  proxy: 'http://127.0.0.1:7890'   # 改成你代理软件的 HTTP 端口
  retry_times: 3
```

修改后重启程序生效。

### 方式三（应急）：指定可直连域名

```yaml
client:
  domain: 'www.cdnhjk.net'   # 或当前可直连的镜像域
```

站点域名变动频繁，这条只做应急，稳定性不如代理。

## 自检步骤

1. 启动程序，搜索任意关键词
2. **能出结果** → 网络通
3. 一直显示「搜索中…」超过 10 秒 → 打开「日志 ▾」看是否有连接超时 / 域名解析失败
4. 打开浏览器访问目标站点，确认代理是否真的生效

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 搜索一直转圈，最后超时 | 代理未开 / 未开 TUN / 端口配错 | 先确认浏览器能打开站点，再回来重试 |
| 浏览器能开，程序不行 | 程序没走系统代理，只配了 TUN 之外的方式 | 开 TUN，或在 `option.yml` 配 `client.proxy` |
| 偶发失败，重试就好 | 站点域名轮换 / 限流 | 等几秒重试；可提高 `retry_times` |
| 下载到一半失败 | 节点不稳定 / 站点限流 | 换节点；已下载的图片不会重复下载 |
| 阅读器打不开页面 | 图片是本地文件，不需要网络 | 检查文件是否完整，或重新下载该本 |

## 为什么不做内置代理

内置代理会带来：节点凭证落盘、隐私与合规风险、以及被滥用为公共出口的可能。
本项目定位是**个人自用工具**，代理由用户自己的系统环境提供。
